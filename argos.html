ARGOS · Cycle

Assurance is a loop, not an annual event.

ARGOS opens a new assurance cycle when a material change invalidates the previous evidence state. The institution knows what changed, which tests must repeat, who decides and what evidence must be retained.

01

Baseline

What exact model, prompt, tool, permission, data and policy configuration is in production?

Version manifest · Agent/tool inventory · Policy/configuration snapshot
02

Observe

What is the deployed system actually doing across tasks, tools, costs, errors, approvals and human interventions?

Runtime traces · Task outcomes · Approval/override logs · Cost telemetry
03

Detect change

Which material change, drift, incident or supplier event invalidates the previous assurance state?

Change event · Drift signal · Incident record · Supplier notice
04

Re-evaluate

Which evaluations, security tests, conformance controls and cognitive controls must be repeated after the change?

Triggered test plan · Regression suite · Control selection rationale
05

Compare

How does the new system state differ from the accepted baseline on quality, safety, authority, cost and human oversight?

Baseline delta · Performance delta · Risk delta · Cost delta
06

Decide

Can the changed system remain in service, require restrictions, rollback, additional approval or withdrawal?

Decision record · Accountable owner · Conditions/limits · Rollback decision
07

Retain evidence

Can the institution reconstruct why the system was considered acceptable at that point in time?

Dated evidence pack · Reviewer record · Versioned test outputs · Decision history
08

Re-open

What future event automatically reopens assurance rather than waiting for a periodic audit?

Trigger rules · Monitoring rule · Scheduled review · Event-driven control

Operating state

Four explicit operating states.

The system is never simply 'compliant'. ARGOS records whether assurance is open, restricted, accepted within scope or withdrawn.

Open

A material trigger has occurred and the previous assurance conclusion cannot be relied upon without re-evaluation.

Restricted

The system may operate only under explicit temporary limits while evidence gaps are closed.

Accepted

The defined evaluation and control set supports continued operation within the stated scope and conditions.

Withdrawn

The system or capability is removed from service because the evidence no longer supports continued operation.
