Claude Code, Codex et Copilot peuvent déjà travailler dans votre entreprise sans être recensés

19 octobre 2026.

Microsoft documente un problème que beaucoup d'entreprises ne savent encore ni mesurer ni budgéter.

Un agent IA peut être créé sur une plateforme interne, ajouté par un partenaire, installé via un SDK ou introduit localement sans déploiement central.

Microsoft étend désormais sa découverte à 60 types d'agents locaux, dont Claude Code, OpenAI Codex et GitHub Copilot.

Une entreprise peut donc dépendre d'agents absents de son inventaire informatique.

Un développeur installe un agent de code. Une équipe ajoute un serveur MCP. Un métier connecte un assistant à sa messagerie.

Ces systèmes obtiennent ensuite des jetons, des accès API, des identités et parfois des droits hérités de leurs utilisateurs.

Le 14 mai, Microsoft révélait un autre signal: 15% des serveurs MCP distants observés par Defender for Cloud étaient sévèrement mal sécurisés et permettaient un accès non authentifié à des données ou capacités internes sensibles.

La supply chain de l'IA commence donc avant le contrat fournisseur.

Elle inclut chaque agent, outil, serveur MCP et dépendance auxquels l'entreprise a déjà ouvert une porte.

ULTRA®

Un SBOM inventorie les composants logiciels.

Une infrastructure agentique exige aussi un inventaire de l'autorité: agent, propriétaire, fournisseur, modèle, outils MCP, identité, permissions, secrets accessibles et agents auxquels il peut déléguer.

Microsoft recommande une identité propre à chaque agent, distincte de celle de l'utilisateur. Les permissions peuvent alors être limitées à une tâche et une durée.

Le 19 octobre, Microsoft pousse cette logique plus loin avec Dynamic Permissions: l'agent reçoit seulement l'autorité nécessaire au travail approuvé.

Le registre doit suivre l'exécution réelle, pas seulement les déploiements déclarés.

LI!GHT WORKFORCE ©

La light workforce fait apparaître une population nouvelle d'acteurs numériques.

Claude Code, Codex, Copilot ou un serveur MCP peuvent écrire du code, interroger une base, modifier un ticket ou déclencher une action sans figurer dans l'organigramme ni dans le CMDB traditionnel.

La capacité qui quitte l'humain est aussi une capacité d'accès et d'action.

L'entreprise doit donc savoir qui possède chaque agent, quelle autorité il détient, quelles dépendances il appelle et comment le révoquer.

KPI: agents découverts, agents sans propriétaire, permissions permanentes, serveurs MCP non authentifiés, délai de révocation.

WOTAN

Wotan pensait connaître tous ses pactes. Son pouvoir commence à lui échapper lorsque leurs conséquences deviennent plus nombreuses que les contrats eux-mêmes.

La première dépendance invisible est celle que personne n'a inventoriée.
