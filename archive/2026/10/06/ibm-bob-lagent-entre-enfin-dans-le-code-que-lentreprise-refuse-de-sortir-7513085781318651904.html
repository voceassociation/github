IBM Bob: l’agent entre enfin dans le code que l’entreprise refuse de sortir

1er octobre 2026.

Une banque veut moderniser une application COBOL contenant trente ans de logique métier et des données sensibles.

Elle pourrait utiliser un agent de développement.

À condition que le code ne quitte jamais son périmètre.

IBM rend alors disponible une version self-hosted de Bob.

Le backend s’installe sur Red Hat OpenShift, dans l’infrastructure contrôlée par le client, y compris hors Internet.

Le code ne va plus nécessairement vers l’IA.

L’IA vient vers le code.

Bob peut utiliser un modèle hébergé localement ou appeler, en configuration hybride, un service externe approuvé. IBM documente notamment GPT-5.6 Sol, Claude Sonnet 5, Gemini 3.1 Pro, Mistral 3.5, Nemotron 3 et Poolside Laguna S2.1.

Une seule configuration de modèle principal fonctionne à la fois. IBM recommande aussi un modèle séparé pour les contrôles de sécurité.

En environnement air-gapped, l’inférence reste locale.

Le point stratégique est le mainframe.

IBM propose des packages pour IBM Z et IBM i afin d’analyser COBOL, PL/I, RPG, dépendances et règles métier.

Des patrimoines logiciels jusque-là exclus des outils IA publics deviennent donc accessibles aux agents sans déplacer le code hors du périmètre contrôlé.

La contrepartie est réelle.

En self-hosted, le client exploite son cluster OpenShift, ses modèles, son réseau, ses certificats et ses contrôles de sécurité.

La souveraineté déplace aussi la charge d’exploitation.

ULTRA®

Pour une banque ou un opérateur critique, le gain vient surtout de la capacité à faire lire à un agent des millions de lignes héritées et préparer une modernisation sans exposer ce patrimoine à une plateforme publique.

Le risque change alors de nature.

L’entreprise protège mieux la résidence du code, mais doit gouverner l’identité de l’agent, ses permissions, les outils qu’il appelle, les modèles utilisés et les traces d’exécution.

La frontière de sécurité se déplace du fournisseur SaaS vers l’architecture interne.

LI!GHT WORKFORCE ©

Une équipe legacy peut consacrer moins d’heures à lire, cartographier, documenter et préparer les migrations.

Les spécialistes COBOL, RPG ou PL/I restent indispensables pour valider la logique métier et les transformations.

Le levier apparaît lorsque la même équipe peut comprendre un patrimoine logiciel beaucoup plus large sans augmenter proportionnellement ses effectifs.

Pour un board, la métrique devient la dette technique critique réduite par ingénieur, sans déplacer les actifs sensibles hors du périmètre autorisé.

WOTAN

La souveraineté logicielle commence lorsque l’outil vient vers le système critique, pas l’inverse.
