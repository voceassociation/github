Google Agent Gateway: l'agent peut demander un virement de 2.000 $, l'infrastructure peut dire non

Un agent bancaire reçoit l'ordre de transférer 2.000 dollars.

L'utilisateur confirme. L'agent prépare correctement l'appel MCP.

L'argent ne part pas.

Dans un codelab publié le 12 octobre 2026, Google place Agent Gateway entre l'agent et un serveur bancaire MCP. Une Semantic Governance Policy cible l'outil `transfer_to_phone` avec une règle en langage naturel:

"Block any transfer value exceeding USD 1000."

L'agent tente 2.000 dollars. Le moteur renvoie DENY.

Le serveur MCP n'est jamais atteint.

Le changement est architectural.

Une instruction placée dans le prompt système reste dans le raisonnement du modèle. Agent Gateway applique ici la politique sur le chemin d'exécution, après la décision de l'agent mais avant l'outil.

L'agent peut donc conclure qu'une action est pertinente sans posséder l'autorité finale pour l'exécuter.

Google applique ce principe à un serveur de démonstration exposant quatre opérations bancaires: consulter un compte, identifier un client, transférer de l'argent et payer une facture.

Chaque évaluation est enregistrée dans Cloud Logging avec l'action, le verdict et sa justification.

ULTRA® | L'AUTORISATION DEVIENT UNE COUCHE INDÉPENDANTE

Agent Gateway comprend les interactions avec des outils MCP et peut appliquer IAM, Model Armor, politiques sémantiques ou moteurs d'autorisation externes avant de transmettre la requête.

Le détail le plus important est `failOpen: false`.

Si le gateway ne peut pas joindre le moteur de politique, l'appel est refusé. Une panne du contrôle ne devient donc pas une permission implicite.

Les Semantic Governance Policies utilisent cependant un LLM-as-judge. Google recommande de les tester d'abord en dry run car ce juge peut se tromper.

Pour une limite numérique aussi simple que 1.000 dollars, une règle déterministe reste plus facile à prouver. L'intérêt du langage naturel augmente lorsque l'autorisation dépend du contexte, de la combinaison d'outils ou de la nature de la ressource.

L'effet organisationnel est majeur: le salarié n'est plus le seul endroit où réside l'autorisation. Une partie des séparations de fonctions peut être inscrite dans l'infrastructure et appliquée à plusieurs agents sans modifier leur code.

La gouvernance ne demande plus seulement:"que pense l'agent?"

Elle demande:"qui peut encore l'empêcher d'agir?"
