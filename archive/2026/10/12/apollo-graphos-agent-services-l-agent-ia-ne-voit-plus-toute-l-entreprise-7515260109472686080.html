Apollo GraphOS Agent Services: l'agent IA ne voit plus toute l'entreprise par défaut

Un agent doit retrouver le statut d'un client.

L'API peut lui renvoyer davantage: adresse, facturation ou données de compte.

Ces informations entrent alors dans son contexte avant même qu'il ait répondu.

Le 7 octobre 2026, Apollo GraphQL présente GraphOS Agent Services pour traiter ce risque.

GraphOS orchestre déjà plus de 2.000 milliards d'opérations par mois. Agent Services ajoute une couche de contrôle entre les agents et les systèmes de l'entreprise.

L'agent cherche dans un modèle métier commun les données utiles. GraphOS lui attribue une identité propre ou propage celle de l'utilisateur qui l'a mandaté. Les règles d'accès s'appliquent jusqu'au niveau du champ.

Il peut lire le nom d'un client et l'état d'une commande sans recevoir son adresse ou ses informations de paiement.

Apollo classe les champs avec des tags comme "sensitivity:PII" ou "sensitivity:financial". Une règle peut autoriser, masquer ou refuser leur accès selon l'agent ou l'utilisateur.

Un champ refusé peut être retiré avant d'entrer dans le contexte du LLM.

La sécurité ne dépend plus d'une instruction demandant au modèle d'ignorer une donnée qu'il a déjà vue.

Chaque requête laisse aussi une trace d'audit.

Intuit pilote déjà Agent Services. Apollo cite aussi American Airlines, Block et Expedia parmi les entreprises utilisant GraphOS pour leurs systèmes ou leurs agents.

La disponibilité reste ambiguë: Apollo annonce une "public preview", tandis que sa documentation indique encore "private preview" avec accompagnement obligatoire pour l'onboarding.

Le prix spécifique n'est pas public.

ULTRA®

Les API d'entreprise ont souvent été conçues pour des développeurs de confiance, pas pour des machines autonomes.

Le GraphOS MCP Server expose des capacités aux assistants. Agent Services décide ce qu'un agent peut réellement voir ou modifier.

Un compte technique large donne à l'agent des droits indépendants de la personne qui l'utilise. Avec une identité transportée jusqu'à la source, le même agent peut recevoir des réponses différentes selon l'utilisateur.

La décision d'autorisation appartient au moteur de politique, pas au modèle.

LI!GHT WORKFORCE ©

GraphOS Agent Services réduit une partie du travail répétitif autour des connexions, credentials et contrôles reconstruits agent par agent.

Les équipes API Platform, IAM et sécurité restent responsables du modèle métier, de la classification des données et des règles.

À grande échelle, l'autonomie d'un agent dépend aussi de la précision avec laquelle l'entreprise décide ce qu'il n'a jamais besoin de voir.
