GitHub Copilot Computer Use: votre vieux logiciel devient pilotable sans API

Une entreprise utilise encore un logiciel Windows installé il y a quinze ans.

Pas d'API. Pas de CLI. Pas d'intégration MCP.

Jusqu'ici, l'automatiser exigeait une intégration spécifique ou une RPA reproduisant des actions prévues à l'avance.

Depuis le 1er octobre 2026, GitHub Copilot ouvre une autre voie.

Computer Use, disponible en public preview dans Copilot CLI et l'application Copilot sur macOS et Windows, peut lire le contenu accessible et le contexte visuel d'une application, cliquer, saisir du texte, utiliser le clavier, faire défiler l'écran et naviguer entre logiciels.

GitHub vise explicitement les applications legacy et GUI-only dépourvues d'interface programmable.

La frontière avec MCP est importante.

Avec MCP, le logiciel expose une fonction structurée à l'agent.

Avec Computer Use, l'application cible peut ne rien exposer du tout. Copilot utilise son interface graphique comme le ferait un utilisateur.

Un agent peut donc récupérer une donnée dans un navigateur, ouvrir un logiciel interne ancien, remplir un formulaire puis reporter le résultat ailleurs sans disposer d'une fonction "create_report".

ULTRA® | LE LOGICIEL N'A PLUS BESOIN D'ÊTRE AGENT-READY

GitHub lance en parallèle les Dynamic Workflows.

L'orchestration est écrite en code. Certaines étapes restent déterministes. D'autres appellent un ou plusieurs agents, séquentiellement ou en parallèle, puis transmettent leurs résultats structurés à l'étape suivante.

Pour un incident informatique, le workflow peut collecter logs et télémétrie, répartir l'analyse entre plusieurs agents puis reconstruire une chronologie et une cause racine.

Cette architecture limite un problème classique de l'agent entièrement libre: le processus reste explicite et observable.

Computer Use intervient là où aucune interface programmable n'existe.

La différence avec une API reste fondamentale. Une interface graphique peut changer, afficher une fenêtre inattendue ou présenter une ambiguïté visuelle. Le contrôle par permissions, les droits Accessibility et Screen Recording sur macOS, ainsi que les politiques administrateur font donc partie de l'architecture de sécurité.

LI!GHT WORKFORCE ©

GitHub, propriété de Microsoft, étend ainsi l'automatisation à une catégorie immense de logiciels que les agents modernes ne pouvaient exploiter sans projet d'intégration.

Saisie, transfert d'informations, consultation de logiciels legacy et certaines opérations administratives deviennent automatisables avant même la modernisation du système.

L'humain reste nécessaire pour les exceptions et les opérations sensibles.

Le changement économique est ailleurs: une entreprise peut commencer à automatiser un logiciel ancien sans attendre qu'il devienne moderne.
