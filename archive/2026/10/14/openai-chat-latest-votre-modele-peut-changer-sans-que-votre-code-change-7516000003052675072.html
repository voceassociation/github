OpenAI chat-latest: votre modèle peut changer sans que votre code change

Le 7 octobre 2026, OpenAI met à jour `chat-latest`.

Pour l'application, l'identifiant reste identique.

Le système servi derrière cet identifiant peut évoluer.

OpenAI le documente: `chat-latest` pointe vers le modèle Instant le plus récent utilisé dans ChatGPT et son snapshot sous-jacent est régulièrement mis à jour. Pour la production API, OpenAI recommande la famille GPT-6.

Ce détail crée un problème d'assurance.

Une banque valide en septembre un assistant après plusieurs centaines de tests. Le comité risque autorise le déploiement.

En octobre, le snapshot derrière l'alias change.

Aucune ligne de code n'a bougé. Le nom du modèle non plus.

Mais l'objet évalué peut ne plus être exactement celui qui répond.

Sophia Abraham et Ben Bucknall ont étudié ce problème dans "Silent Updates", accepté à AIES 2026.

Ils examinent neuf fournisseurs d'API de première partie et sept hébergeurs d'inférence. Aucun fournisseur de leur échantillon ne permet à un tiers de vérifier de bout en bout que l'artefact servi est bien celui auquel se rapporte l'évaluation publiée.

Le risque dépasse les poids du modèle.

Ajustement fin, classifieur de sécurité, prompt système, récupération documentaire ou routage peuvent modifier le comportement observable sans changer l'identifiant public.

Une gouvernance qui enregistre seulement "GPT-6", "Claude" ou "Gemini" peut donc conserver une identité administrative stable alors que son objet technique a changé.

ULTRA®

LA PREUVE DOIT SUIVRE L'INFÉRENCE

Le point difficile est le seuil de réévaluation.

Tout changement fournisseur ne justifie pas un audit complet. Abraham et Bucknall proposent trois déclencheurs: changement de capacité, dérive comportementale mesurable et modification d'un composant susceptible d'affecter le risque.

Pour un système critique, le registre devrait conserver la version évaluée, les tests associés et les changements fournisseur détectés. Une régression significative doit pouvoir déclencher une nouvelle validation.

OpenAI illustre l'autre cas avec un cycle de vie explicite. Le 1er octobre, l'entreprise a annoncé l'arrêt de GPT-5.1, GPT-5.3-Codex et GPT-5.4-Nano au 1er avril 2027, avec modèles de remplacement recommandés.

Ici, la migration possède une date.

Avec un alias mouvant, le changement peut intervenir sans modification de l'identifiant utilisé par l'application.

Pour un board, un test n'est une preuve que si l'organisation peut encore relier cette preuve au système qui répond aujourd'hui.

La date de déploiement ne suffit plus.

Il faut une chaîne de garde entre évaluation et inférence.
