Oracle FSCR: une partie du métier d'intégrateur ERP devient un dépôt GitHub

26 octobre 2026.

Une entreprise déploie Oracle Fusion.

Il faut traduire ses processus, choisir les options, respecter les dépendances, configurer, tester puis valider.

Une partie de ce savoir repose encore sur des consultants qui connaissent l'ordre exact des opérations.

Oracle vient d'en publier une partie sous une forme inhabituelle.

Fusion Setup and Configuration Registry, ou FSCR, est un dépôt GitHub public qui transforme l'expertise de configuration d'Oracle en skills lisibles et exécutables par des agents IA.

Options, dépendances, séquences, exécution, tests, validation: Oracle maintient cette connaissance parallèlement à Fusion Applications.

Un agent peut convertir exigences métier, politiques internes ou configuration existante en runbook, exécuter les changements dans Fusion, tester puis soumettre le résultat à un expert.

Le savoir d'implémentation devient versionné.

L'architecture compte.

Le modèle interprète la demande.
FSCR fournit la connaissance produit.
Fusion reste le système transactionnel.
L'expert conserve la revue et l'approbation.

Oracle précise ses limites: FSCR n'est pas couvert comme une fonctionnalité Fusion. Il exige un environnement autorisé, des permissions adaptées et une revue avant exécution.

AI Success Navigator s'appuie sur cette base. Son Configuration Agent construit les configurations; le Testing Agent prépare les tests; l'Integration Agent peut définir l'architecture d'une intégration et produire son code.

Accenture, Deloitte, Grant Thornton et PwC soutiennent l'initiative.

Le signal économique est clair: les intégrateurs pourront bâtir leurs méthodes et solutions sectorielles au-dessus d'une base Oracle commune plutôt que reconstruire la configuration projet après projet.

Lexington Health affirme avoir réduit de 80% certains efforts de design et de configuration. Retour client, pas performance généralisable.

ULTRA®

FSCR transforme une partie de la documentation produit en couche exécutable.

La connaissance de configuration peut désormais évoluer avec le logiciel, être versionnée, appelée par un agent puis contrôlée humainement.

L'avantage concurrentiel des intégrateurs se déplace vers ce qu'Oracle ne peut pas encoder complètement: processus sectoriels, exceptions métier, architecture cible, gouvernance et conduite du changement.
