Un agent commence une tâche dans une application.

Il peut appeler un outil avant de suspendre son exécution pour une validation humaine.

Il peut appeler un outil avant de suspendre son exécution pour une validation humaine.

Pour l'utilisateur, cette activité doit devenir visible quelque part.

Jusqu'ici, chaque équipe reconstruisait souvent sa propre couche d'interaction: flux temps réel, état de session, appels d'outils ou reprise après interruption.

Le 25 septembre 2026, Microsoft annonce, avec CopilotKit, un SDK .NET pour AG-UI, "Agent-User Interaction Protocol".

AG-UI standardise ce qui circule entre un agent et l'application visible par l'utilisateur.

Le serveur peut émettre des événements typés comme RUN_STARTED ou STATE_DELTA. L'interface les interprète sans connaître le cadre logiciel qui exécute l'agent.

Un même point de terminaison peut ainsi alimenter plusieurs surfaces, d'une application web à Teams.

AGUI.Server expose un agent compatible. AGUI.Client permet à une application .NET de consommer un agent distant. Le flux utilise par défaut SSE.

Le protocole transporte aussi les demandes d'approbation. L'interface renvoie la décision de l'utilisateur puis l'agent poursuit.

Microsoft a déplacé son propre Agent Framework vers les paquets AGUI.* plutôt que de maintenir une implémentation séparée.

La couche d'interaction devient indépendante du cadre qui exécute l'agent.

ULTRA®

Cette séparation peut modifier le coût réel d'un projet agentique.

Une partie du travail d'ingénierie ne porte pas sur l'intelligence de l'agent, mais sur le dialogue entre son exécution et l'interface humaine.

AG-UI cherche à rendre cette couche réutilisable.

Le SDK .NET est publié en cinq paquets NuGet sous licence MIT et reste compatible avec les SDK TypeScript et Python. Une application .NET peut donc consommer un agent écrit ailleurs sans changer le contrat d'échange.

Mais AG-UI ne sécurise pas l'agent.

Une approbation correctement transportée ne garantit pas que la personne dispose des droits nécessaires ni que l'action soit acceptable. Les permissions et les règles de contrôle restent à construire autour.

MCP standardise progressivement l'accès de l'agent aux outils. AG-UI standardise la manière dont son activité revient vers l'utilisateur.

Le light workforce apparaît côté logiciel: moins de code spécifique lorsque le même agent doit exister dans plusieurs produits.

La valeur ne vient donc pas uniquement d'un agent plus capable.

Elle vient aussi d'une architecture où chaque nouvelle interface exige moins de travail.

MERCURIO

Une infrastructure devient industrielle lorsque la même capacité peut changer de surface sans devoir être reconstruite.
