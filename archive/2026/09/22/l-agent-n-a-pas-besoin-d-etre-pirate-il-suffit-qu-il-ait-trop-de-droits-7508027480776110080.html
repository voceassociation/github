L'agent n'a pas besoin d'être piraté. Il suffit qu'il ait trop de droits.

Vous demandez à un agent de préparer un dîner en consultant votre calendrier et vos courriels.

Vous demandez à un agent de préparer un dîner en consultant votre calendrier et vos courriels.

Pendant sa recherche, il rencontre un contenu malveillant lui demandant de récupérer un code de réinitialisation dans Gmail puis de l'envoyer vers un autre site.

OpenAI utilise ce type de scénario pour expliquer le risque des injections de prompt.

L'agent n'a cassé aucun mot de passe.

Il a utilisé les accès qu'on lui avait donnés.

C'est là que commence la gouvernance de l'IA agentique.

Un chatbot produit du texte.

Un agent peut lire un dossier, appeler une API, modifier un fichier, envoyer un message, exécuter du code ou déclencher une action.

OpenAI recommande donc de limiter les applications accessibles à celles réellement nécessaires. Dans ses Workspace Agents, les actions d'écriture sont réglées par défaut sur "Always ask".

Mais l'approbation humaine possède elle-même une faiblesse.

En mars 2026, Anthropic révèle que les utilisateurs de Claude Code approuvent environ 93% des demandes de permission.

Une validation humaine n'est donc pas automatiquement un contrôle humain.

Quand on clique presque toujours sur "autoriser", la sécurité peut devenir un rituel.

La vraie question est ailleurs: que peut faire l'agent si le modèle se trompe, si un document le manipule ou si l'utilisateur valide trop vite?

Le principe du moindre privilège devient alors central.

Un agent qui résume des contrats n'a pas besoin de pouvoir les supprimer.

Celui qui prépare un e-mail n'a pas besoin de pouvoir l'envoyer.

Celui qui cherche une facture ne devrait pas hériter de tous les droits du propriétaire de la messagerie.

Pour une organisation, cela change la cartographie du risque.

Le danger d'un agent dépend moins de la seule puissance du modèle que de la combinaison entre son identité, ses permissions, les outils auxquels il accède et son degré d'autonomie.

Un board peut approuver une politique IA raisonnable tout en laissant subsister un risque majeur si personne ne gouverne cette couche d'exécution.

La politique dit ce que l'agent devrait faire.

L'architecture détermine ce qu'il peut réellement faire.

ULTRA®

Le 28 juillet 2026, la nouvelle spécification MCP rend ce contrôle beaucoup plus concret.

Les noms des méthodes et des outils peuvent désormais apparaître dans les en-têtes HTTP "Mcp-Method" et "Mcp-Name".

Un API Gateway peut reconnaître qu'un agent tente d'appeler un outil précis, appliquer une règle, mesurer l'appel ou le bloquer avant qu'il n'atteigne le système cible.

La gouvernance ne repose plus uniquement sur le prompt ou sur la prudence du modèle.

Elle peut être imposée dans l'infrastructure.

Demain, demander "quel modèle utilisez-vous?" ne suffira plus.

Il faudra aussi demander: avec quelle identité agit-il, à quels outils a-t-il accès, et qui peut réellement l'empêcher d'agir?
