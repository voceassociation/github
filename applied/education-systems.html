Concept · Proposed programmes and architecture

VOCE Education Systems

A proposed approach for educational institutions, universities and administrations: assess needs, design programmes and test the learning architecture before deployment. Pilot projects remain to be defined with each institution.

Discuss a pilot

Assessment

Examine learners, languages, digital access, target skills, existing systems and responsibilities. Deliverable: diagnosis and proposed scope.

Curriculum Design

Define skills, progression, professional tasks, support and assessment. Deliverable: curriculum dossier and competence matrix.

Virtual Faculty Pilot

Run a bounded experiment with reference teachers and volunteer learners. Deliverable: protocol, actual observations, costs and revision decisions.

Institutional Deployment

Condition expansion on results, security, human capacity and permissions. Deliverable: responsibilities, operating plan and skills transfer.

Controlled architecture

Approved, versioned content feeds a retrieval layer. The orchestrator limits tools by role. Code exercises use isolated execution, quotas and network access closed by default. Assessment applies explicit tests and criteria; a model may explain a result without independently awarding a qualification. Logs connect content version, assistance, learner work and human review.

Qwen · API · MCP

Qwen and other accessible-weight models are options to assess against licences, language performance and hosting constraints. Selection remains open. Identity, learning data and assessment records should be exportable in documented formats.

Learner protection

Before a pilot, minimise data, define purposes, permissions and retention, document providers and support correction, appeals and deletion. Exams and consequential decisions retain appropriate human validation. Deployment involving minors requires additional assessment. Sensitive profiling is not a default requirement.

Reviewable deliverables

The dossier should separately estimate curriculum preparation, language review, infrastructure, inference, human supervision, security and maintenance. Assumptions, capacity limits and exit conditions must be explicit. No price or efficiency result is established before this work.

Frameworks and scope

e-CF / EN 16234-1:2019 supports professional ICT competence design; DigComp 3.0 supports transversal digital skills; ESCO identifies occupations and skills. Montenegro’s national framework and vocational or university requirements must be examined for the relevant institution and programme. ISO 21001:2025 is a voluntary management reference, not a certification claim. Detailed mappings require documentation before programme validation.

FR · EN · IT · Montenegrin

Technical language will require a versioned glossary, review by a competent native speaker with subject knowledge and learner comprehension testing. Montenegrin terminology requires dedicated validation. No Montenegrin edition is currently presented as available.

Concept · Proposed programmes and architecture

Concept → development → pilot → verified deployment. Moving between stages requires deliverables and evidence; no pilot or government partnership is presented as established.
