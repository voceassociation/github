An agent becomes institutional infrastructure when identity, tools, permissions and consequences converge.

The VOCE Agent Infrastructure Reference defines a vendor-neutral control architecture for institutions deploying AI agents in Europe. It connects API contracts, MCP, A2A, workload identity, authorization, data, observability, continuous assurance, economics and regulation in one operating model.

01

Eight principles before the first agent acts.

Identity before action

Every executing agent or workload receives an attributable identity distinct from the human, model or service that initiated it.

Least authority

Tools, data scopes and transaction limits are granted per task and remain revocable.

Contracted interfaces

APIs and inter-agent messages are typed, versioned, validated and observable.

Traceable delegation

The institution can reconstruct who delegated which authority, to which agent, for what purpose and duration.

Observable execution

Model calls, retrieval, tool use, handoffs, approvals, failures, costs and actions form one traceable execution record.

Human authority

Material workflows identify an accountable owner, escalation path and executable stop mechanism.

Reversibility

A model, tool or supplier can be restricted or replaced without rebuilding the institution around it.

Regulatory mapping

European obligations are applied to the actual role, sector and risk classification of the system.

02

The ten-layer agent control stack.

01

API and tool contracts

OpenAPI 3.2.x and JSON Schema make capabilities explicit. Material write operations define schema, errors, idempotency, versioning, rate limits and transaction ceilings.

02

MCP

MCP 2026-07-28 provides the model-to-tool and context layer. Its stateless core improves ordinary HTTP scaling; authorization remains an institutional control, never a side effect of interoperability.

03

A2A

A2A 1.0 handles agent-to-agent discovery and task exchange across vendors. AgentCards, handoffs, cancellation, provenance and cross-agent data policy become governance objects.

04

Workload identity

SPIFFE/SPIRE can give software actors short-lived cryptographic identities. Human identity and software identity remain distinguishable throughout delegation.

05

Authorization

OAuth security practice plus policy-as-code separates authentication from permission. The decision is explicit: principal, action, resource and context, with default deny and step-up approval.

06

Data, memory and RAG

Provenance, version, access rights, deletion, retention, memory expiry and regional routing follow information from source system through retrieval and agent memory.

07

Observability and audit

OpenTelemetry-style traces record agent, workflow, model, retrieval, tool calls, approvals, latency, cost and exceptions while keeping sensitive content under a separate telemetry policy.

08

Continuous assurance

Task evaluation, permission tests, prompt-injection tests, red teaming, regression, incident replay and tested kill switches follow every material system change.

09

Economic authority

Budget is a permission. Institutions govern cost per completed task, retry budgets, model routing, anomaly thresholds and supplier concentration.

10

European regulatory overlay

AI Act, GDPR, DORA and NIS2 are mapped only where the organisation, use case and legal role make them applicable. Compliance evidence is attached to the system architecture.

03

Five operating levels, five different control burdens.

A0 · Assistant

Generation or retrieval without external action authority. Minimum: session identity, data boundary, source provenance and output review.

A1 · Tool-connected agent

Approved read or low-impact tools. Add tool inventory, per-tool authorization, traces, limits and revocation.

A2 · Delegated action agent

Business actions under bounded authority. Add workload identity, policy decision point, transaction limits, approval gates, idempotency and rollback.

A3 · Multi-agent operating system

Agents coordinate models and tools across systems. Add MCP/A2A governance, delegation chain, shared observability, routing policy and continuous evaluation.

A4 · Critical agent network

Material regulated, financial, clinical, infrastructure or public-service consequences. Add board owner, independent assurance, incident exercises, exit plan, evidence pack and tested emergency stop.

04

Europe changes the evidence burden.

The EU AI Act does not turn every agent into a high-risk system. It does make role and classification explicit. For systems that fall within high-risk obligations, the legal architecture includes logging, transparency to deployers, human oversight and deployer duties. Article 50 transparency obligations have applied since 2 August 2026 for relevant interactive and generative systems. GPAI provider obligations have applied since 2 August 2025, with Commission enforcement powers applying from 2 August 2026.

Sector overlays remain decisive. A financial institution subject to DORA remains responsible for ICT third-party risk even when an agent, cloud provider or model vendor performs the technical work. Critical and important functions therefore require dependency registers, contractual controls, resilience and exit thinking alongside AI governance.

VOCE · Orchestration

The score is written before the orchestra accelerates.

Agentic systems distribute execution across models, APIs, identities and institutions. VOCE treats the architecture as a score: each actor keeps a defined register, entrance, authority and stop condition. The purpose is not aesthetic. It is operational accountability.
